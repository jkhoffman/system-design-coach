# Code review: `codex/refactor-interview-lifecycle`

Reviewed 2026-09-17 against `main`, at commit `fa930ea`.

Ten findings survived verification, ranked most severe first. Findings 1 and 3 are confirmed from the code. Finding 2 could not be checked against the live OpenAI API. Finding 9 is a missing safeguard rather than a demonstrated failure.

Recommendation: fix findings 1–4 before merging. Finding 2 needs one real (non-mock) API call to settle.

## High severity

### 1. A transient connect failure permanently burns the session

`src/lib/sessionCommands.ts:23`

`reserveSessionStart` only accepts `status='created'` (main also allowed `'live'`), and the route flips the row to `'live'` before the client has applied the SDP answer.

Failure scenario:

- POST `/api/live/session` succeeds and `completeSessionStart` sets `status='live'`.
- Then `setRemoteDescription` throws, ICE fails, or `session.started` does not arrive within the 60s startup wait.
- `useInterviewController` (lines 133-139) dispatches `connection_failed` and calls `router.refresh()`.
- `InterviewRoom` (lines 74-96) then renders only "Connection interrupted / Review saved progress". The error text and the Join button are in the other branch, and any retry returns 409.

On main the user returned to the lobby and could rejoin.

### 2. Strict structured-output schemas may be rejected by OpenAI

`src/lib/modelFormats.ts:6`

Strict structured-output formats are now generated by `zodTextFormat` from the runtime Zod schemas, so they carry `default: ""` (PromptSpec context), `minLength`/`maxLength`, `minItems`/`maxItems`, `minimum`/`maximum` and `$schema`. OpenAI strict mode is reported to reject non-null `default`. Main's hand-written schemas had none of these keywords.

Failure scenario:

- Real (non-mock) `/api/prompts/generate` and `/api/prompts/expand` calls would get 400 "'default' is not permitted" from OpenAI and return 502, so custom prompt setup never works.
- `GRADE_FORMAT` (line 5) carries `minimum`/`maximum`/`maxLength`/`minItems`, which may hit the same rejection and fail every grade.
- `scripts/mock-openai.mjs` dispatches only on format name and never validates the schema, so e2e stays green either way.

Not checked against the live API.

### 3. A stale finish from a second tab silently wins

`src/app/api/sessions/[id]/route.ts:29`

Finish is now first-write-wins and returns 200 `{applied:false}`, but the client never reads `applied`.

Failure scenario:

- Tab A is live. The same `/interview/<id>` URL is opened or reloaded in tab B, which shows "Connection interrupted", and the user clicks "Review saved progress".
- `recoverSavedInterview` PATCHes a finish built from the page-load transcript and timeline, and the session ends.
- Tab A's real finish gets `applied:false`. `persistFinalSession` treats that 2xx as success, and A navigates to review.
- Grading then runs on the stale checkpoint. The live tab's real final transcript, scene and image are discarded.

On main the later finish overwrote the earlier one.

### 4. Older graded sessions can hang on the grading screen

`src/lib/legacyContracts.ts:11`

`normalizeLegacyGrade` returns `undefined` when a stored grade fails the new stricter `GradeReportSchema` (`startMs >= 0`, 20k string cap).

Failure scenario:

- A session graded under main has, for example, `moments[].startMs = -1`; main's schema and validator set no minimum.
- The review page sees grade `undefined` and renders `GradeGate`.
- `/status` reports `grading_status 'done'`, `watchJob` calls `onDone`, `router.refresh()` runs, and the grade is still `undefined`.
- Polling has stopped and no error was set, so "Generating your scorecard…" shows forever.
- POST `/grade` returns 409 because status is `'graded'`, and `claimJob` requires `grade IS NULL`, so the session cannot be regraded.

## Medium severity

### 5. Large recordings fail on every retry

`src/app/api/sessions/[id]/recording/route.ts:44`

A single 45s `AbortSignal` now covers all four fetch attempts, the 2.5s retry delays, and the entire streamed WAV download and disk write. Main had no deadline.

Failure scenario:

- A 45-60 minute stereo WAV is hundreds of MB (`MAX_RECORDING_BYTES` is 2 GiB). It cannot download in what remains of the 45s after the retries, so the pipeline aborts, `failJob` marks the job failed, and the `.part` file is removed.
- "Retry recording" runs under the same budget and fails again.

Related:

- The fetch loop has no try/catch, so a thrown network error or abort skips the remaining retries and the "network error" fallback is dead code. This part also exists on main.
- Grading now uses a 110s timeout with `maxRetries: 0`, so transient 429/5xx responses become user-visible failures.

### 6. Moving the repo or data directory breaks artifacts

`src/lib/artifacts.ts:76`

Artifact paths are stored as absolute paths, and `within()` throws outside the try/ENOENT block. `availableRecording`'s destructive reset also now runs on every GET `/status` poll (on main the reset happened only on POST).

Failure scenario, after the repo or data directory is moved or copied:

- `readFinalImage` throws an `HttpError` instead of falling back to the inline image. The image route has no catch, so it returns 500.
- `gradingImages` throws, so grading calls `failJob` and returns 502 on every retry.
- Each review visit polls `/status`, which calls `availableRecording` and then `resetMissingRecording`. That nulls `recording_path` even when the WAV still exists at the old location. The client then re-downloads from OpenAI, where the content may already have expired.

### 7. Failed whiteboard exports use up snapshot slots

`src/components/useBoardSync.ts:68`

`lastSnapshotMs` and `snapshotCount` now advance before the PNG export, so a failed or null export consumes one of the 12 snapshot slots and starts the 45s cooldown. Main incremented only after a successful export.

Failure scenario: the board is momentarily empty (`exportPng` returns null), or a large board hits the new 10s export deadline, which is caught and turned into null. Each attempt still uses a slot and starts the cooldown with nothing recorded. A few slow exports leave the review and the grader with few or no milestone snapshots.

### 8. The review page polls even when the recording is ready

`src/components/ReplayScrubber.tsx:16`

`ReplayScrubber` ignores the server-rendered `session.hasRecording` and `recordingStatus` and always starts from `{status:'idle'}`, so it polls `/status` on every review visit.

Failure scenario:

- Every review visit of a session with a ready recording first shows "Downloading the recording…" until `/status` responds. Main rendered the audio element immediately and did not poll.
- If three `/status` loads fail or time out (10s each), `pollJob` calls `onError` and the red error and Retry button appear over an existing recording.
- Each poll also triggers the state-mutating `availableRecording` call described in finding 6.

### 9. `endInterview` has no recovery path

`src/components/useInterviewController.ts:75`

`await closing` and `structuredClone(finalPayload)` run after `endedRef` is set with no try/catch, and `endInterview` is invoked with `void`.

Failure scenario:

- `dc.close()`, `pc.close()` or a cleanup callback throws inside `shutdown()`, or `structuredClone` hits a non-cloneable value.
- The rejection is swallowed, phase stays `'ending'` with error null, and `InterviewRoom` shows Retry only when error is set.
- `finalPayload` is null, so `saveAndFinish` returns silently, and `endedRef` blocks a second `endInterview`.
- The session stays `'live'` with only the last checkpoint.

Main wrapped `close()` in try/catch and built a plain object instead of cloning. The verifier could not construct a realistic throw, so this is a missing recovery path rather than a demonstrated failure.

### 10. Upstream OpenAI sessions are orphaned on three exits

`src/app/api/live/session/route.ts:84`

After the upstream OpenAI live session is created, three failure exits return without closing it or recording its id: the missing-`liveSessionId` 502, `signal.throwIfAborted()`, and the lease-lost 409. The abort and 409 exits, and the missing-id condition on the 502, are new.

Failure scenario:

- The client's startup abort fires, or the start lease expires and is taken by another request, just after the OpenAI create returns.
- The route returns 500 or 409 and the `finally` block only releases the reservation.
- The upstream session is orphaned, possibly still recording, and the user can start a second billed session for the same interview.

Also, a response that has the SDP but no id now blocks the interview entirely, where main started it and only lost the recording.

Main never closed upstream sessions either, so the missing close itself is not new. How long an orphaned session lives upstream, and what it costs, is not visible in the code.

## Minor cleanups

Verified, but below the cut of ten:

- `src/app/api/sessions/[id]/recording/route.ts:33` re-reads the row and never uses the result.
- `src/lib/boardExport.ts:31-37` stacks two 10s deadlines on one export call.
- `src/app/api/sessions/[id]/snapshot/route.ts:11` parses the multi-MB body before checking that the session exists and is live.
- `endInterview` closes the transport before the board flush, so the final whiteboard-state message is dropped. This has no visible effect.

Reported but not verified:

- `src/lib/db.ts` and `src/lib/sessionDto.ts` are an unused shim, which leaves three row mappers for the same table.
- `src/lib/traceContracts.ts:67` validates every trace event three times on each 5-second checkpoint.
- `findSession` and an inlined `validSessionId` check are used inconsistently across routes.

## Refuted and dropped

- The 128KB default body limit.
- Append-latency ack matching in `src/lib/liveTraceAnalysis.ts`, which real traces show works.


## Remediation disposition — 2026-09-17

The original findings above are retained as the review record. The implementation now addresses each finding as follows:

Mock now validates nested schemas. | Serialized-format assertions and mock prompt/grading requests. **Live acceptance unverified**; `scripts/probe-model-schemas.mjs --live` probes both configured models using synthetic inputs. The unverified/refuted minor findings did not justify deleting live helpers or adding speculative optimizations.

Validation passed: type generation/type checking, ESLint, all 71 deterministic tests, Webpack production build, and the expanded mock browser suite (9 mock live creates, 8 mock grades, 7 mock recording downloads). Live schema probes have not been run; mock success is not live-provider verification.
